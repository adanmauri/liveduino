# 0014. Firmware is bundled and flashed in pure Python

**Status:** Accepted · **Date:** 2026-10-08

## Context

A board needs StandardFirmata before liveduino can drive it
([ADR-0009](0009-firmata-is-implemented-in-house-over-standardfirmata.md)). Getting it there used
to mean installing the Arduino IDE, or arduino-cli and avrdude, picking the sketch and flashing it.
The ATmega328 family flashes through its bootloader with STK500v1 over the serial port. The
`avr-gcc` in the `arduino:avr` core produces different bytes on macOS and Linux, even with the same
pinned versions.

## Options

- **Document the Arduino IDE steps:** nothing to maintain, but a toolchain to install before the
  first line of Python.
- **Call avrdude:** reliable, but an external binary per platform.
- **Bundle prebuilt images and flash them in Python:** no toolchain for users, but images to build
  and a programmer to maintain here.

## Decision

- `liveduino-cli flash <board>` writes a bundled image with a pure-Python STK500v1 programmer and
  Intel HEX parser (`src/liveduino/programmers/`).
- The images ship in the wheel under `src/liveduino/firmware/`, one per board and Firmata variant,
  indexed by `manifest.json` with a sha256 per image. A board declares its sketches (`fqbn`,
  `firmware_sketch`, `firmware_sketches`); what does not build is recorded as unsupported.
- The images are generated by `make firmware` (`scripts/build_firmware.py`, arduino-cli) with the
  core and library versions pinned in the `Makefile`, and are a **CI/Linux artifact**: the
  Firmware workflow verifies the bundle against a fresh Linux build and regenerates it on demand.
  Images built on macOS are never committed.

## Consequences

### Positive

- From `pip install` to a working board with no Arduino tooling.
- The bundled bytes are reproducible and checked on every change to boards or firmware.

### Negative / trade-offs

- Only bootloaders that speak STK500v1 are covered; Caterina/AVR109 (Leonardo, Micro) and
  SAM-BA (MKR, Nano 33 IoT) are on the roadmap (`TODO.md`).
- Firmware cannot be regenerated locally on macOS for commit, only through CI.
- The wheel grows with each board and variant.
